# TulparHub — передача разработчикам

B2B/B2C маркетплейс запчастей для грузовой и спецтехники в Казахстане (КАМАЗ, MAN,
DAF, Volvo, Scania, HOWO, Shacman и др.) + аренда спецтехники. MVP собран, задеплоен
и работает. Этот документ — обзор для новых разработчиков; технические детали см. в
[README.md](README.md) и [DEPLOY.md](DEPLOY.md).

- **Репозиторий:** https://github.com/tulparhubkz/tulparhub
- **Staging (живой):** https://tulparhub.onrender.com
- **Задачи / бэклог:** [Issues](https://github.com/tulparhubkz/tulparhub/issues) ·
  [Project board](https://github.com/orgs/tulparhubkz/projects/1)

## 1. Стек (актуальный)

| Слой | Технология |
|---|---|
| Frontend / API | Next.js 14 (App Router), TypeScript, React |
| Стили | Чистый CSS (без Tailwind), переменные в `app/globals.css` |
| База данных | PostgreSQL + Drizzle ORM (самостоятельно размещаемый) |
| Авторизация | Auth.js (NextAuth v5) — Google **live на staging**; роли retail / b2b / admin |
| Тесты | Vitest (юнит, в CI) + Playwright (smoke, в CI при наличии секрета БД) |
| Стейт на клиенте | Zustand + localStorage (корзина, избранное); гараж синкается в БД у залогиненных |
| Инфраструктура | Docker Compose (Postgres + Next + Caddy auto-TLS) |
| Хостинг | Staging — Render (Frankfurt) + Neon Postgres; prod-цель — KZ VPS |

> Раньше проект был на Supabase + Vercel — выполнена миграция на самостоятельно
> размещаемый PostgreSQL/Drizzle и Docker. Источник каталога — CSV-выгрузка прайса
> вендора (`scripts/import-csv.ts`), в будущем — 1С. Дизайн рассчитан на нескольких
> вендоров, сейчас активен один.

## 2. Что уже работает

**Каталог** — ~20 280 деталей и ~121 680 строк остатков по складам, импорт из CSV
(идемпотентный, с журналом `sync_runs`). Фильтры (бренд, OEM/аналог, наличие, цена,
категория). Поиск по артикулу, названию и **VIN** (автоопределение марки/модели).
Карточка товара: наличие по складам, цена розница/опт (B2B), кросс-номера, аналоги.

**Корзина и заказы** — реальные заказы в `orders`/`order_items`: серверный пересчёт
цен (розница/опт по роли сессии), доставка в итоге, счёт на оплату
`/invoice/<uuid>` (доступ: гость — по UUID, юзер — по своей сессии), гостевое
отслеживание `/track` (номер + телефон, анти-перебор), «Мои заказы», привязка
гостевого заказа к аккаунту в один тап на order-success. Ops-уведомления в
Telegram. Rate limiting per-IP на заказы/лиды/трекинг.

**B2B-цены** — `price_b2b` отдаётся только сессиям с ролью b2b/admin (сервер
гейтит DTO и пересчёт заказа); роли выдаются в `/admin/users`.

**Админка `/admin`** — заказы (статусы, оплата), заявки (звонки/брони/запросы цены
с воркфлоу «обработан»), журнал импорта, пользователи (роли).

**Избранное** (`/wishlist`), **Мой гараж** (VIN-декодер по WMI + NHTSA-фоллбэк;
у залогиненных живёт в БД, localStorage импортируется при первом входе),
**Помощь в подборе** (`/vin`).

**i18n RU/KZ/EN** — типизированные словари с паритетом ключей; серверные
сообщения тоже переводятся (экшены возвращают ключи).

**SEO/PWA** — robots, sitemap (~5k URL), метаданные PDP, hreflang, install-манифест
с иконками.

**Mobile-first UI** — нижняя навигация, 375px без горизонтального скролла,
клавиатурный фокус, AA-контраст; storefront смоделирован по autopiter.kz;
дизайн-токены в `globals.css`.

## 3. Чего ещё нет (бэклог)

Всё ведётся в [Issues](https://github.com/tulparhubkz/tulparhub/issues) и на
[доске](https://github.com/orgs/tulparhubkz/projects/1) (метки `feature`, `infra`,
`blocked`, `good first issue`). Главное:

- **Оплата** (#21) — нет интеграции с провайдером; ждёт решения по Kaspi /
  Freedom Pay / Halyk ePay.
- **SMS** (#39 → #46) — шлюз не выбран; блокирует SMS-OTP-логин и полный вариант
  привязки заказов по телефону.
- **Prod-хостинг** (#40) — домен + KZ VPS; staging живёт на Render free tier.
- **Реквизиты счёта** (`INVOICE_*` env) — счёт печатается с баннером «черновик»,
  пока CEO не даст реальные реквизиты.
- **Метрика** (#44) — ждёт counter id; **юр. страницы** (#43) — ждут текстов.
- **Мультивендор** (#22) и **реальные фото** (#23) — Wave 2; у большинства товаров
  фото по категории.
- **Точный подбор по VIN** — текущий декодер приближённый (WMI + NHTSA); для
  production-точности нужна интеграция TecDoc/Laximo.

## 4. С чего начать новому разработчику

1. Поднять локально по [README.md](README.md) (Docker + `yarn dev`).
2. Прочитать раздел **«Как мы работаем»** и **«Подводные камни»** в README.
3. Взять задачу с меткой **`good first issue`** в Issues, сделать ветку → PR.

## 5. Что обсудить с командой

1. Оплата: Kaspi vs Freedom Pay vs Halyk ePay (блокирует #21).
2. SMS-шлюз и альфа-имя (блокирует SMS-OTP #46 и phone-claim в #48).
3. Реквизиты для счёта (`INVOICE_*`) и Метрика counter id (#44).
4. Переезд staging → prod: домен + KZ VPS (см. [DEPLOY.md](DEPLOY.md)).
5. Нужна ли интеграция TecDoc/Laximo для точного VIN-подбора (платная).
6. Данные фида: у поставщика есть битые цены (см. предупреждения `yarn import-csv`).
